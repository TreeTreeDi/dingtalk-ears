# 钉钉消息助手重构方案

日期：2026-10-29。状态：用户已确认并完成实施，具体使用方式见安装文档。

补充要求：配置示例、DWS 安装与授权、profile 与本人/群 ID 获取、Codex 登录、凭据复用、前后台启动及排错必须写清楚。具体使用约定见 [安装配置与启动](安装配置与启动.md)；其中待实现接口需与最终代码同步，不能只有文档。

## 目的与现状

让其他人使用自己的钉钉和 Codex 登录身份启动项目，让后续维护能够按职责定位代码。

当前三个 Python 文件同时承担监听、调度、数据库、Web 接口和外部命令执行；大量压缩语句影响阅读。账号、本人 ID、群 ID、路径和固定端口散落在代码及启动项里。HTML 内嵌 CSS，没有包元信息、开发工具链或安全的分享产物。

已有 19 项测试建立重构基线，全部通过；HTTP 测试需要允许本机端口绑定。当前运行服务的 transport 报告 degraded，不能将 listener ready 当作连接健康证据。

## 方案取舍

建议保留 Python 标准库 + 原生 HTML/CSS/JavaScript，以模块边界和配置注入解决问题。换成 Web 框架或前端框架需要额外依赖及迁移，本次没有业务需求支持这种成本。只格式化原文件无法解决配置复用与分享问题。

## 配置及分发

- 明确配置 profile、self_id、关注群 ID 和名称、显示名称、端口、状态目录、DWS/Codex 可执行文件、聚合间隔。示例只有占位符，不含个人身份。
- 运行时从显式配置路径读取，缺失身份或格式错误时在建立订阅之前报错。路径相对配置文件解析，避免依赖执行目录。
- 本地个人配置和所有数据库、日志、摘要、状态、截图不得进入分享包；分享脚本只收录允许的源码、示例、文档和工具配置。
- CLI 提供初始化配置及依赖检查；其他用户分别登录 DWS 和 Codex。Node 只用于开发检查，运行面板不需要 npm 启动或前端构建。
- 本次首先支持当前使用 fcntl 的 macOS/Linux；macOS 提供基于实际 Python、路径和用户 UID 生成的登录启动项。Windows 不宣称已支持。
- 当前 Python 3.7 兼容性保留；开发工具可使用独立的较新 Python，兼容范围必须经测试说明。

## 现有数据与行为

- 保持原数据库结构，当前本机配置指向原数据目录，避免迁移导致重复处理或发送。源码与运行数据分离。
- 保留人工审查后发送、幂等保护、结果不明不重发、已投递隐藏、待办确认、来源原文约束和 OA 排除。
- UI 使用配置中的群名及真实监听数量；transport degraded/连接异常应可见，不能因 ready 标志而显示健康。
- macOS caffeinate 接电防睡眠行为保留；不增加无界的进程或订阅重试。
- 完成离线验证后再切换本机服务，保留可回退备份。测试不发送钉钉消息，不创建真实待办。
